что делает. Актуально на текущую версию. Строки указаны для быстрого перехода
(могут сместиться при правках — ориентируйся на имя функции).

## 2. Единая модель результата — `core/report/schema.py`

Всё, что возвращают методы. Понять эту структуру важно для добавления методов.

| Объект | Строка | Что это |
|---|---|---|
| `StatResult` | 46 | Главный контейнер результата (см. поля ниже) |
| `Estimate` | 34 | Точечная оценка + доверительный интервал |
| `Warning_` | 25 | Предупреждение (о нарушении допущений и т.п.) |
| `Severity` | 16 | Уровень: info / warning / error |
| `StatResult.add_warning(code, message, severity)` | 62 | Добавить предупреждение к результату |

**Поля `StatResult`:** `method` (имя), `estimates` (список оценок), `statistics`
(словарь чисел: t, F, p и т.д.), `p_value`, `warnings`, `parameters` (произвольные
данные — сюда кладут остатки, summary, comparisons), `n`, `seed`, `data_quality`.

## Как добавить новый статметод (общая схема)

1. **Написать функцию** в подходящем файле `core/stats/*.py` — принимает данные,
   возвращает `StatResult`. Заполнить `statistics`, `p_value`, `estimates`,
   при нарушении допущений — `add_warning`.
2. **Написать тесты** в `tests/test_<модуль>.py` — сверка с scipy/statsmodels
   или ручным расчётом.
3. **Добавить в каталог** `core/validation/catalog.py` — запись `MethodSpec`
   (label, group, слоты колонок, параметры), чтобы метод появился в витрине.
4. **Перевести** название в `core/validation/catalog_i18n.py` (EN, PT).
5. **Прописать в мост** `web/src/pyodide/bridge.ts` — в `METHOD_MODULES` путь
   импорта, при необходимости в логику `runMethod` (как получает данные).
6. **Пересобрать ядро** — `python build_core.py`.

Пункты 1-2 — всегда. 3-5 — если метод должен быть в интерфейсе.
